# cdiscdata — Architecture

## Package overview

`cdiscdata` is a data-only R package with no compiled code and no runtime
dependencies. It bundles versioned CDISC Controlled Terminology and Define-XML
file assets. All data is loaded lazily (`LazyData: true`).

## CT data model: validity-date design

All historical CT versions are stored in a single table using a
**validity-date design** rather than one table per version.

Each row represents a unique **term-state** — a specific set of values for a
term at a point in time:

| Column | Description |
|--------|-------------|
| `codelist_code` | NCI C-code for the codelist (e.g. `"C66731"`) |
| `codelist_name` | Submission value for the codelist (e.g. `"SEX"`) |
| `codelist_label` | Long name |
| `extensible` | Logical — whether sponsor extensions are allowed |
| `term_code` | NCI C-code for the term; `NA` for codelist-level rows |
| `term` | Submission value; `NA` for codelist-level rows |
| `decoded_value` | NCI preferred term |
| `synonyms` | Pipe-separated synonyms |
| `definition` | NCI definition |
| `valid_from` | Date of first CT release with this term-state (**never NA**) |
| `valid_to` | Date of last CT release; `NA` = still current |

### Update logic (`apply_ct_update`)

When a new NCI release is applied:
1. **New terms**: key not in current table → add row with `valid_from = release_date`
2. **Retired terms**: key in current but not in new release → set `valid_to = release_date - 1`
3. **Changed terms**: key in both but value differs → close old row, add new row
4. **Identical terms**: no change → no new row added

### Querying a version

```r
tbl[tbl$valid_from <= query_date &
      (is.na(tbl$valid_to) | tbl$valid_to >= query_date), ]
```

## `get_dataset()` routing

```
get_dataset(name, version)
    │
    ├── type == "CT"         → .get_ct_dataset()  → filter validity-date table
    ├── type == "Schema"     → schema_path(.resolve_schema_version())
    └── type == "Stylesheet" → stylesheet_path(.resolve_schema_version())
```

## `schema_path()` / `stylesheet_path()` version discovery

Available Define-XML versions are read from `inst/extdata/schema/` at runtime
by listing subdirectories matching `define-xml-X.Y`. This means adding a new
Define-XML version only requires adding files — no code change needed.

## Raw cache

NCI text files are large (~5 MB each uncompressed). The cache stores parsed
data frames as compressed `.rds` files (`compress = "xz"`), reducing 402 MB
of text to ~39 MB. A date is "done" when its `.rds` file exists, regardless
of whether it produced new rows in the CT table (some releases are identical
to the prior one).
